Authorization · Java

keycloak-authz-lab

Four roles, one resource, four different documents — and the matrix is the test suite.

The problem
Most projects that “have role-based authorization” document it in a wiki, a comment, or someone's head. The matrix exists, but it is not executable, so it does not fail when it breaks.

This lab inverts that: the authorization matrix is the test code. The domain is deliberately boring — one invoice with seven fields — because the only thing that matters is that those fields carry different sensitivity, and that four roles see four different projections of the same resource. Put internalMargin in the wrong projection and the suite goes red before the pull request exists.

A field a role may not see is absent from the JSON. It does not come back as null, because null tells the caller the field exists and leaks the shape of what they cannot have.

The trade-off I took
Two strictly separated test levels instead of one. A slice suite with simulated JWTs runs on plain mvn test with no Docker, so the matrix is checked on every machine in seconds; a Testcontainers suite that boots a real Keycloak sits behind its own Maven profile. Two suites cost more to maintain — the payoff is that nobody skips the fast one.

Microservices · Java 25 / Spring Boot 4

digital_booking

Six services for an accommodation platform — and the same product built again as a monolith, on purpose.

A booking platform for the Cesar and La Guajira departments of Colombia — houses, apartments, cabins and fincas. Six Spring Boot services on Java 25, a React 19 front end, the whole stack up with one docker compose up.

The decision worth defending
Microservices from the first commit, not monolith-first — and I pay the bill for it in this repo: six copies of the security and config boilerplate, and more orchestration than a domain this size needs.

So I built the same product a second time as a single NestJS + Angular process, in a separate repository, and the comparison is the deliverable. The monolith is the one that fits free-tier hosting, because PaaS bills per service and six Java containers plus MySQL do not fit. Microservices buy independent deploy and scale at the cost of infrastructure you either absorb or pay for — writing both is how I learned what that sentence actually costs.

Two more calls, each with an ADR in the repo: schema per service inside one MySQL instance, no cross-schema foreign keys — data ownership stays clean without running three database engines; and static path routing instead of a discovery server, because Eureka at six fixed services is machinery that earns nothing.

Product · NestJS + Angular · Deployed

Corpus Damana

A study app for dʉmʉna, the language of the Wiwa people of the Sierra Nevada de Santa Marta.

Concordances, a frequency dictionary, spaced-repetition flashcards, and a translator that answers only from what the corpus actually attests. That constraint is the whole design: for a language with a few thousand documented forms, a model that fills gaps with plausible invention produces confident nonsense, and confident nonsense is worse than no answer at all. The corpus is imported from CSV into a local store; the model composes from retrieved passages rather than from memory.

Why it is here
It is the one you can open and use without cloning anything. NestJS and Angular workspaces, Node 22, deployed on Render.

Library · Rust

dian-ubl

Colombian electronic invoicing, with no floating point anywhere near money.

A library and CLI that builds and validates electronic invoices in the UBL 2.1 profile DIAN, the Colombian tax authority, requires: a typed domain model, exact integer-scaled monetary arithmetic, the DIAN NIT check-digit algorithm, CUFE computation over SHA-384, and deterministic UBL serialization.

The design decision
The validator reports every problem it finds, each anchored to a field path, instead of stopping at the first. An invoice rejected four times for four different reasons is four round trips with the tax authority — and the authority is not a fast API.

v1 is implemented and green, with input fixtures and normative golden files. The public contract — types, signatures, error codes, XML shape — is frozen in the README. XAdES signing, web-service submission and numbering-range resolution are explicitly out of scope, and saying so is part of the contract.
